# Передача проекта: «Хрупкий мир» (World in Pieces)

Этот файл — всё, что нужно новому помощнику (человеку или ИИ), чтобы продолжить разработку с того же места.
Версия на момент составления: **1.8.7** (см. `package.json`). Владельцы: Воробьев Александр Сергеевич, Никифоренко Екатерина Эдуардовна
(см. `LICENSE`). Общаться с владельцем нужно по-русски, коротко и по делу.

## Что это
Браузерная RPG «три в ряд» на поле 6×6: карта из шестиугольников с деревней, бой против существ (ИИ ходит сам), 4 фракции
(люди, гномы, эльфы, ящеры), снаряжение, магия, питомцы, медали. Чистый HTML/CSS/JS без сборки; выкладывается на GitHub Pages
(репозиторий `world-in-pieces`). Мир, графика и названия полностью свои; чужие игры не копируем.

## Главный документ
**`docs/design.md`** — полное описание: правила боя, фракции, монстры, экономика, история всех версий и решения владельца.
Читайте его первым. Графика: `docs/art-spec.md` (какие файлы ждёт игра), баланс: `docs/balance.md`.

## Структура
- `index.html`, `css/style.css` — страница и оформление (три варианта боя; по умолчанию №3 «колонки»).
- `js/` — модули игры. Ключевые: `engine.js` (поле и правила, без интерфейса), `combat.js` (бой), `ai.js` (противник),
  `balance.js` (все числа), `game.js` (экран боя), `mapview.js`/`hexmap.js`/`mapart.js` (карта и деревня),
  `screens.js` (окна зданий, стена доблести), `tutorial.js` (обучение у Бобра), `ammo.js` (боеприпасы), `market.js` (Торговые ряды), `story.js` (стражи и сюжет), `inventory.js` (профиль и сохранение в localStorage), `items.js`/`tiers.js`/`parts.js`
  (вещи), `bestiary.js`/`monsterart.js` (существа), `art.js` + `art-files.js` (подключение готовых картинок).
- `art/` — готовые картинки (WebP). Где файла нет — игра рисует встроенные SVG-заглушки.
- `tests/` — тесты, `tools/` — инструменты, `docs/` — документация и снимки для README.

## Как работать
- Запуск: открыть `index.html` в браузере (сервер не нужен). Тесты: `npm test` (18 наборов, должны проходить все).
- Подключить новую графику: положить PNG в папку, затем `python3 tools/build-art.py <папка>` (нужны Pillow и scipy). Имена
  файлов берутся из `docs/art-spec.md`; скрипт сжимает в WebP, раскладывает по `art/` и перезаписывает `js/art-files.js`.
- Проверка в браузере: `node tools/smoke.js` (страница без ошибок), `node tools/screenshots.js` (обновить снимки в `docs/`).
  Нужен Playwright.
- Одностраничный просмотр: `python3 tools/bundle.py` создаёт `gem-match-preview.html` (картинки внутри).
- Баланс: `node tools/balance.js --n=60 --tiers=1,4,7,10`; цель — «Равный» бой ≈ 55–80% побед, разброс между фракциями
  не больше ~5 пунктов; после правок магии, монстров и расходников всегда пересчитывать.

## Правила владельца (обязательные)
- Версия всегда из трёх цифр вида 1.3.4: последняя цифра 0–9, после 9 растёт средняя (1.3.9 → 1.4.0). Двузначных чисел (1.2.13) быть не должно. Пакеты 1.2.10–1.2.13 переименованы в 1.3.0–1.3.3.
- Поле с камнями не должно сдвигаться во время игры ни от каких действий (подсказки, сообщения, обучение, кнопки): оно стоит на одном месте.
1. **Версии идут подряд, прибавляя по единице к последней цифре. После 1.1.x — 1.2.0, дальше 1.2.1, 1.2.2…** (решение владельца). Ничего не пропускать.
   Число в `package.json`, имя архива `world-in-pieces-v<версия>.zip`, тег на GitHub `v<версия>`.
2. **Каждый выпуск отдаётся комплектом:** полный архив + части меньше 100 файлов каждая (лимит загрузки GitHub через
   сайт; с 1.2.8 частей четыре — картинок стало больше) + этот файл `HANDOFF.md` отдельным файлом для скачивания + обновлённое описание `docs/design.md`.
3. Подписи при загрузке на GitHub: `v<версия> (1/4): код и тесты`, `(2/4): графика героев и вещей`, `(3/4): существа, собеседники,
   руны, магия, ресурсы, камни`, `(4/4): карта и интерфейс`; потом релиз с тегом `v<версия>`. Предпросмотр (`tools/bundle.py`)
   ужимает крупные картинки только в своей сборке — лимит артефакта 16 МБ.
4. Любое изменение — с тестом; не ломать старые сохранения (профиль дополняется недостающими полями).
5. Не копировать чужие игры (названия, картинки, раскладки) — только вдохновляться.
6. Править именно то, что просили. Если трактовка неясна — спросить, а не угадывать (ошибка с «обсидианом ×5» заняла четыре
   попытки именно из-за неверной трактовки).
8. **Графику не ужимаем ради предпросмотра** (решение владельца, 13.10.2026): если страница-превью перестаёт влезать в лимит артефакта 16 МБ, качество картинок игры не снижается — урезается сам предпросмотр (например, часть картинок в нём не показывается), а выпуск идёт обычным порядком.
7. Названия и тексты в игре — по-русски. Репозиторий и заголовок README — английское имя `World in Pieces`.

## Что важно знать про правила боя (самое хрупкое)
- **Обсидиан ×5** — камень обсидиана с номиналом x5, собранный в любой линии: в том же проходе убирает все камни вокруг на
  расстоянии 1 (до 8, с диагоналями), потом камни падают и сдвигаются вправо. За соседей — ресурсы; урон — только за
  соседей-обсидиан (или при активной Шаровой молнии). Цепная реакция между соседними x5. Код: `Engine.obsidianBurst`.
- Камни после сбора падают вниз, затем сдвигаются вправо; новые появляются, только когда поле пусто или нет ходов.
- Линия 4+ даёт дополнительный ход (4 — x2, 5 — x3, 6 — x10). Неверный ход — штраф 5% ХП; 3 подряд — поражение. Ход — 30 секунд.
- Магия: у каждого заклинания своя цена (`Balance.magic.costs`), часть открывается по уровню героя.
- Дикий гриб: настоящий двойник (второй противник) по заряду спор. Питомцы: настоящий бой 2 на 1.

## Языки (русский и английский) — с 1.4.7

- Любой текст для игрока в коде пишется через `_t('Русский текст')` или со вставками `_t('Получено {0} монет', [n])` (вместо `{0}`, `{1}` подставляются элементы массива). Без `_t` текст останется русским и в английской версии.
- Английские переводы — в `js/en.js`: ключ — русская строка из кода, значение — перевод. Правка перевода = правка значения в этом файле, код трогать не нужно. Нет перевода — игра покажет русский.
- Надписи в `index.html` (кнопки, подсказки) переводятся автоматически по тому же словарю (ключ — текст с одним пробелом между словами).
- Язык: выбор игрока (кнопка «EN/RU» на карте, хранится в localStorage `wip-lang`) → язык браузера (ru/uk/be/kk → русский, остальное → английский). Для площадок (Яндекс Игры, VK): до загрузки скриптов задать `window.WIP_LANG = 'ru' | 'en'`. Переключение перезагружает страницу.
- Проверка: `node tools/i18n-extract.js` (нужен acorn: `ACORN_PATH=путь/к/acorn`) показывает строки без перевода и русский текст вне `_t`; `tests/i18n.test.js` (в `npm test`) следит, чтобы у каждой строки был перевод с теми же `{0}` и HTML-тегами.
- Скрипты `i18n.js` и `en.js` стоят первыми в `index.html` и в сборке. Переводы сделаны сразу на весь текст; шутки и голоса героев стоит вычитать глазами в игре.
- Испанский добавляется так же: новый словарь `es.js` (по образцу `en.js`) и ещё одно значение в `i18n.js`.

Ночь 21:30–5:30; плавная смена света по ключам `LIGHT`; погода — по **трёхчасовым блокам** суток, одинаковая у всех в один час (хеш даты и номера блока, поэтому прогноз вперёд честный): ясно 40, облачно 28, дождь 15, туман 8, гроза 3, ливень 3, густой туман 3 (редкая непогода ≈ 9%). `forecast(t, n)`, `warning(t)` (непогода идёт сейчас или начнётся в ближайшие 3 ч), `local(kind, biome)` — вид явления по местности (снег вместо дождя и грозы, метель; в пустыне дождя нет, песчаная буря, знойная дымка, пыльная мгла; **правила боя от местности не зависят**), `span(мин)` — «40 мин» или «3 ч».

## Пакет 1.7.0 (выпущен 13.10.2026) — осада деревни
Решения владельца: волна из 3–5 существ **цвета героя** подходит к воротам; бои — обычные, вручную; осада приходит **только раз в календарные сутки** (не «раз в N побед»), не раньше 5-й победы и только пока игрок на карте. Если время вышло, а враги остались, они уносят часть монет и одну пачку ресурсов (не больше 10%, меньше с ростом Ратуши) и становятся «похитителями» на карте ~30 минут: победа над похитителем возвращает его долю.
- **Модуль `js/siege.js`** (без интерфейса, тест — `tests/siege.test.js`, в `npm test` после world): `due(last, now, wins)` (раз в сутки, `MIN_WINS=5`), `size(tier)` 3/4/5 (цвет ≥4 / ≥8), `defense(hall)` → `{volley, minutes, theft}`, `make`, `kill`, `theft`, `split`, `expire`, `liveLooters`, `killLooter`, `rewardCoins`, `sane` (проверка сохранённых данных).
- **Защита деревни** зависит от уровня Ратуши L = `Village.lvl(Profile.data.village,'hall')` (0–5): башни у ворот снимают с врага перед боем `volley = 8% + 3%·L` ХП (до 23%), забор держит осаду `8 + L` минут и прячет добычу: теряется `10% − 1%·L` (не меньше 5%). Обстрел применяется в `setupMonster` (`js/game.js`, `sel.volley`), в бою пишется строка «Башни обстреляли врага: −N% ХП»; у питомца в двойном бою поле врага режется так же. Окно «Ратуша» (`siegeLine()` в `js/screens.js`) показывает текущую и следующую защиту.
- **Состояние**: `Profile.data.map.siege` (текущая осада: `raiders[]`, `t0`, `t1`, `over`, `looters[]`, `lootEnds`) и `Profile.data.map.siegeLast` (`{day, wins}`). При загрузке данные проверяет `Siege.sane`; осада, закончившаяся, пока игрока не было, тихо снимается (тост «Осада закончилась, пока вас не было»).
- **Карта** (`js/mapview.js`, блок «1.7.0» перед `tick()`): `siegeCheck()` из `tick()` (каждые 5 с) запускает осаду, если пора; не запускает при хеше `#dev-…` (тесты), до 20 с после входа, при открытом окне, боевом режиме, подземелье, фракции. Существа — на свободных сотах у двух случайных ворот (`siegeCells()`), токены с пульсирующим кольцом (золотое — осада, голубое — похититель, `renderSiegeTokens`), красные точки на мини-карте, красные огни у ворот (`#l-amb.siege`). Полоса `#siege-strip` («⚔ Осада: отбито N из M · осталось м:сс») — нажатие переносит камеру к ближайшему врагу. Карточка врага (`showRaider`) — обычная карточка существа + пояснение об обстреле; кнопка «Подойти и напасть» (`data-act="siege"`) → `siegeFight` → `startSpecial({siege, siegeKind, volley})`.
- **Исход**: победа над врагом → `siegeWon` (счётчик, при последнем — `siegeVictory`: монеты `Siege.rewardCoins(World.cacheCoins(цвет), всего)` и до 2 ресурсов, карточка «Осада отбита!»). Время вышло → `siegeExpire`: кража (`Siege.theft`), оставшиеся становятся похитителями, карточка «Осада не отбита!». Бой, идущий в момент окончания срока, продлевает осаду на минуту (`Siege.GRACE_MS`).
- **Проверка**: `MapView.devSiege()` в консоли форсирует осаду (для теста), `MapView.siege` — текущее состояние. Проверено в браузере (компьютер 1280×800 и телефон 390×844): запуск, карточка, обстрел, победа над всеми, срок вышел → кража → похитители → возврат добычи, бой с питомцем; `npm test` зелёный. ## Пакет 1.6.6 (выпущен 12.10.2026) — износ и починка, рецепты Кузницы, правило слабых существ
Решения владельца (ответы на 13 вопросов предложения 1.6.5 и его идея про слабых существ), всё внедрено:
- **Прочность** (`js/items.js`: `durMax/durOf/repairCost/wearFactor/setTier`): максимум по цвету 1…10 = 30, 35 … 75 (`25 + 5·цвет`). В записи вещи хранится только `dur` (текущая); поля нет — вещь целая (старые сохранения; `dur` равный максимуму НЕ хранится — на этом держится проверка `SaveGuard`). −1 за поражение у всех надетых вещей, кроме сумки (поводок, компас, метательное, амулет считаются). При 0 вещь снимается и не надевается до починки (`Gear.canEquip`). Улучшение цвета сохраняет долю прочности. Продажа надетой вещи (Лавка, Старьёвщик, Торговые ряды): цена × `0,5 + 0,5·прочность/максимум`.
- **Починка** — вкладка «Починка» в Кузнице (`js/screens.js`, `forge`): полная починка = ⅓ цены новой вещи, пункты пропорционально (не меньше 1 монеты); +1 / +5 / +10 / полностью / «Починить всё»; скидка народа на Кузницу действует. Прочность видна на карточках, в окне вещи и на экране поражения.
- **Поражения** (`Profile.battleStart/battleMoved/battleEnd`, поле `data.battle = {moved}`): сдача после первого хода и проигрыш по таймеру — поражение (−1); бегство до первого хода — не поражение; **закрытая посреди боя вкладка после первого хода = поражение с −2** (`settle()` при следующей загрузке, сразу пишется в хранилище, на карте — сообщение).
- **Правило слабых существ** (`Bestiary.rollDrops(…, heroTier)`, `Bestiary.resourcesWeak`): существо слабее цветом героя **не даёт ресурсов** (монеты и опыт остаются); так же для событий карты. На экране награды и в карточке существа есть пояснение. Это оставляет ресурсы для малых уровней на рынке.
- **Рецепты Кузницы** (`js/forge.js`, подключён в `index.html` после `hexmap.js`; `Gear.craftCost` теперь вызывает `Forge.recipe`): цена вещи в Кузнице — 50% цены Лавки (обычная) и 40% (редкая, эпическая); 20% этой суммы — монеты мастера, остальное — ресурсы по цене продажи. Ресурсы выбираются по **ролям** (металл, пластины, дерево, кожа, обвязка, тайное, трофей): берётся первый вид роли, у которого на цвете есть источник (≥ 0,89 штуки за бой у лучшего существа; считается из `HexMap.SPAWN` и `Bestiary.MONSTERS`, поэтому пересчитывается сам при смене диапазонов). ### Режим 2 (реальное время): аудит случайности боя (19.10.2026)
- `tools/determinism-audit.js` (браузер, в `npm test` не входит): один и тот же бой дважды с одним зерном `Math.random`, при разном времени анимаций, сравнивается шаг в шаг. Результат: бой воспроизводится точно (39 шагов, 145 957 вызовов random, совпало и при таймингах 5 и 40 мс). Значит, согласованный бой по сети возможен.
- Что мешает (работа на режим 2): 1) весь бой берёт случайные числа из `Math.random` (`rnd`, `boardRand`, `Combat.hit/monsterTurnStart/useConsumable…` по умолчанию, подсказка хода `AI.choose` тоже тянет random) — нужен отдельный общий генератор боя `BattleRand` по зерну, не `Math.random`, и подсказка/косметика (капли на экране `game.js` ~2794) не должны его трогать; 2) бой не симметричен: `playerMove`, заклинания и расходники жёстко заточены под сторону `left`, а `right` ведёт ИИ — нужно управлять `right` по сети; 3) обе стороны должны считаться только по карточке (народ, уровень, вещи), без питомца, эликсиров, благословений, умений из профиля — тогда это и «равные условия» для турниров.

Тест `tests/battlerand.test.js` (охрана на число Math.random в combat.js/game.js). Дальше: пункт 3 (бой только по карточке), затем 2 (ходы стороны по сети + WebSocket).

### Режим 2, пункт 3 — готово: бой только по карточке

### Режим 2, пункт 2, этап А — готов сервер боя в реальном времени (`server/src/live.js`)
WebSocket `/live` (пакет `ws`): вход `{t:'hello', token}` (тот же токен сессии), очередь `{t:'queue', card}` (подбор по уровню в пределах ARENA_SPREAD, 20 с ожидания → `noopp`), комната: зерно, роли A/B, `first`; ходы `{t:'act', n, a, done}` пересылаются по порядку (владелец хода, нумерация), таймер хода 30 с (+2 с запас) → `timeout`, 3 пропуска подряд = поражение; итог `{t:'result', winner}` от обоих (расхождение/молчание = ничья); обрыв: `resume` с `have`, сервер досылает пропущенные ходы. Сервер бой НЕ считает. Тесты: `server/tests/live.test.js` (ядро с поддельными часами + настоящий WebSocket). Дальше этап Б: клиент — ходы правой стороны из сети (`netSide`), ход/заклинание → `act`, зеркальная симметрия RNG, проверка двумя браузерами.

### Режим 2, пункт 2, этап Б — готов клиент живого боя
- `js/live.js` — клиент связи (очередь, ходы по порядку, возврат после обрыва, `next()` отдаёт ходы соперника); `Net.current.remote.liveAccess()` даёт адрес и токен.
- Схема «зеркала»: у каждого игрока он слева, соперник справа; оба клиента считают бой по одному зерну (`BattleRand.seed`) и ходы друг друга. Свои действия → `LIVE.net.act` (`mv` ход камнями, `cast` заклинание с клеткой, `inst` заклинание без цели, `lm` шаровая молния, `end` конец хода с отпечатком состояния). Ход соперника выполняется той же дорогой, что у ИИ за правую сторону: `liveRemoteTurn` / `liveApply` (game.js).
- Сверка: в `end` едет отпечаток (`liveHash`: ХП, камни, щит, поле); при расхождении бой прерывается без результата («Бой прерван»). Отладка: `window.__LIVE_DEBUG = true` — в `end` едет и полное состояние (`window.__desync`).
- Равные условия: карточка вместо профиля (`cardFight`, `myGear` из `Duel.toShadow(myCard)`); в живом бою выключены сумка, боеприпасы, эликсиры, умения фракции (способность по заряду), медали, руны, питомец, благословения. Условие дня арены не применяется.
- Время: сервер ведёт ход (30 с, «пропуск» → `timeout`, 3 подряд = поражение), локальный таймер в живом бою только показывает; сдача (`Отступить`) = поражение (`forfeit`).
- Интерфейс: Арена → «Игроки» → «Живой бой» (поиск до 20 с; никого нет → подсказка вызвать тень).
- Проверка: `tools/live-e2e.js` (два браузера + сервер в памяти; `XP=3000000` — уровень 100 с открытыми заклинаниями, `FORCE=kind,..` — принудительные заклинания, `SCENARIO=timeout|forfeit|offline`, `TURN_MS`). Проверены без расхождений: ход, шаровая молния, огненный крест, захват, превращение, выпад, удар, зеркало, прилив, жертва, прорицание, исцеление, хаос; пропуск хода, сдача, обрыв связи. НЕ проверено: «Кулак ярости» (fury) — в e2e пропущен, на сервере/клиенте работает как остальные, но отдельно не гонялся.
- Известные ограничения/идеи: способности фракции по заряду отключены (нужна доработка по сторонам); карточка клиента подделываема (серверная проверка нужна для рейтинга/турниров); лента рейтинга живых боёв пока общая с ареной (World.arenaResult).
