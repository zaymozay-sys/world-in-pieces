# Автоматический игрок для «Хрупкого мира»

Это браузерный тестовый игрок, а не бот с платным API ИИ. Он запускает реальную игру через Playwright (Chromium), использует **отдельный браузерный контекст** и не обращается к личным сохранениям игроков.

## Что он делает

- Проходит стартовый сценарий: создание нового героя, выбор фракции и имени.
- Проверяет карту и главное меню, убеждается, что подменю **скрыты до нажатия**, раскрывается ровно одна панель, а сама панель находится слева от основного меню.
- Ищет доступное существо по данным игровой карты и начинает обычный бой игровым методом. Ходы внутри боя выполняет **встроенный автопилот самой игры**. Результат боя определяется игровым движком, награды не подменяются.
- Проверяет экран результата, возвращение на карту и сохранение после перезагрузки.
- В режиме `full` проводит **10 последовательных боёв одним героем**, учитывает победы, поражения, опыт и монеты, а также записывает полученную добычу: новые вещи, ресурсы, расходники и эликсиры. Сравнивает реальное состояние инвентаря до и после каждого боя; дополнительно сохраняет текст и значки наград с экрана результата.
- Проверяет сохранение после 1-го, 5-го и 10-го боёв в `full`-режиме. В `smoke` проводит один бой. Новый режим `soak` проходит **100 боёв подряд одним героем**, проверяет сохранение после 1-го, 5-го, 20-го, 40-го, 60-го, 80-го и 100-го боёв; делает скриншоты при поражениях, после 1-го и каждого десятого боя. Для всех ста боёв записывает статистику и добычу.
- Запускает интерфейс на английском на телефоне, а в полном режиме — ещё и в альбомной ориентации.
- Сохраняет JSON-, Markdown-отчёты и снимки экрана; в случае ошибки тест завершается с ненулевым кодом.

**Ограничение:** бот ещё не выбирает ходы на поле match-3 самостоятельно, не открывает всю цепочку построек и не имитирует реальные касания по карте. Он выбирает обычного противника из игрового состояния, а сам бой отдаёт игровому автопилоту. После поражения не выдаёт себе опыт или предметы. Изменения инвентаря отражают чистую разницу запасов; если предмет был получен и потрачен за один бой, его выдача может быть видна только в скопированном тексте наград.

## Как запускать

В корне репозитория:

    npm ci
    npx playwright install chromium
    npm run test:player

Это короткий режим: один бой на компьютере и проверка меню на английском на телефоне.

Для расширенной проверки (**10 боёв подряд** одним героем с отчётом о победах, поражениях, опыте, монетах и добыче, плюс проверка альбомного экрана):

Linux/macOS:

    WIP_PLAYER_MODE=full npm run test:player
    WIP_PLAYER_MODE=soak npm run test:player

Windows PowerShell:

    $env:WIP_PLAYER_MODE='full'; npm run test:player
    $env:WIP_PLAYER_MODE='soak'; npm run test:player

Отчёты: test-results/game-player/report.md, report.json и изображения PNG.

В GitHub Actions тест запускается через локальный HTTP-сервер (`http://127.0.0.1:8765`), а не через `file://`: это ближе к реальному развёртыванию игры и исключает нестандартизированное поведение браузерного хранилища у локальных файлов. При каждом контрольном обновлении страницы в журнал пишутся состояние `localStorage`, длина сохранения, его основные поля, а также признаки `storageOk` и `stale`. Это позволяет отличить ошибку записи от ошибки загрузки.

Можно запускать против локально поднятой игры через переменную WIP_URL (без адреса использует локальный index.html). **Не запускайте тесты на настоящем аккаунте**: тестовый сценарий создаёт новый профиль в изолированном браузере.

## GitHub Actions

Workflow: .github/workflows/game-player.yml.

- При изменениях кода в ветке main запускается короткий smoke-тест.
- Ночью (03:17 UTC) запускается расширенный тест на 10 боёв.
- Если в сообщении коммита есть `[test:10]`, даже при обычном push запускается 10 боёв. `[test:100]` запускает 100 боёв. Иначе после изменений запускается короткий тест.
- Максимальное время задания — 90 минут. Тест `soak` не отменяется при последующих коммитах; это может увеличить использование минут GitHub Actions.
- В разделе GitHub **Actions → Game player — browser smoke and full journey → Run workflow** можно вручную выбрать smoke, full или soak.
- После запуска в карточке выполнения откройте **Artifacts → game-player-report** — там отчёт и скриншоты.
- Если запуск красный, смотрите шаг Run test player и report.json / failure*.png.

Если в репозитории Actions отключены организационными настройками, включить их может владелец. Зелёный результат означает прохождение именно описанных сценариев, **не доказательство отсутствия всех игровых ошибок**.

В проекте уже существуют дополнительные проверки: npm run test:e2e, npm test, npm run career. Они дополняют автоматического игрока.
